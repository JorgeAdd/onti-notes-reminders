# Design: Slice 9 — How it works help

## Technical Approach

Web only. A lazy `features/help/` module (pure `help-model`, presentational content, one dialog shell, an in-house focus-trap hook) is opened from the Today page only: the new `?` command in `reduceKey` and a Statusline "?" button. Today owns one `helpOpen` flag, mirroring the capture bar, tag bar and sheet. While it is true the existing key layers are off. Serves the proposal, `docs/roadmap.md` Slice 9 (binding), R11, SG10, SG13-SG16, SG20. No API, schema or CONTRACT change. Scope decision (orchestrator): All notes and the note view have no `?` and no button.

## Data Flow

    `?` key ─▶ reduceKey ─ {type:'help'} ─▶ useTodayRows.bar.onHelp ─┐
    Statusline "?" ─ onHelp(button) ────────────────────────────────┴▶ TodayContainer.openHelp(from) ─ helpOpen, returnTo
    helpOpen ─▶ bar.open / searchAvailable off (keys inert) ─▶ DayPage ─ lazy HelpDialog(mobile ? dock : portal)
    HelpDialog ◀─ buildHelp(touch=mobile) ◀─ messages (statusline.keys, note.hints, help.*)
    esc / close / scrim ─▶ onClose ─▶ helpOpen=false ─▶ useFocusTrap cleanup focuses returnTo

## Risks and contradictions (sources not changed)

- CONTRADICTION: `openspec/config.yaml` `rules.tasks` caps a PR at 400 lines and asks for chained PRs; this slice's decision is 800 and then `size:exception` single PR. Following the orchestrator; flagged for the human.
- CONTRADICTION: SG10 lists `↵ open/fold body`; no Today key handler does that (Enter only works on native buttons). Help follows the code and omits it.
- Roadmap lists `e`/`d` under "On a note", but on Today `d` does nothing and `e` needs a focused row; the rows carry a detail line. With Today-only help, the note-view keys are not discoverable from inside the note view (accepted by scope decision).
- Statusline grows to 44 px (rule 11): a visible change to boards 03/05; verify on screenshots.
- Desktop portal and a trap listener on `document` assume no other modal; none exists today.
- `messages.ts` is a collision-prone file (add `help` as one block before `errors`).
- The skill caps design at 800 words; this one is longer on purpose (seven requested decisions, as in the slice 4 precedent).
