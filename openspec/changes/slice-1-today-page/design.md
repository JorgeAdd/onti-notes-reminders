# Design: Slice 1 — Read-only Today page

## Technical Approach

The server decides **which notes are on the page** (shared `buildDayPage` + `todayWindow`, R1-R5, via a `Clock` port and the profile timezone, as `authenticated`/RLS per ADR-001). The client decides **how time reads** (R6 labels, NOW line, copy) from the server's `now`, ticking each minute. API stays hexagonal (CLAUDE.md 15-16); web is container/presentational with semantic tokens only (rules 8-12). Serves proposal anchors R1-R6, R15, R16, C1/C3/C4/C7, SG1-SG8/13-16/18.

## Data Flow

    browser ──Bearer──▶ GET /today ─▶ authenticate ─▶ getToday(identity)
                                        │  clock.now(), profiles.findOwn, notes.listOwn (asUser/RLS)
                                        ▼  buildDayPage(notes, now, tz) ─▶ z.encode ─▶ JSON
    TodayContainer (useQuery) ─▶ DayPage ─ useNow(skew, 1 min) ─▶ relativeTo / rail-model / statusline
                 └─ refetch: window focus │ now ≥ window.end

## Interfaces / Contracts

```ts
const instant = z.codec(z.iso.datetime(), z.date(), {
  decode: (s) => new Date(s),
  encode: (d) => d.toISOString(),
})
// ports.ts
interface Clock {
  now(): Date
}
interface NoteRepository {
  listOwn(identity: Identity): Promise<NoteRecord[]>
}
```

UI notes: `rail-model(items, now, tz)` is pure and yields `hour | item | now | gap` rows from local hours of items and `now` only (never enumerates instants). More than 6 timed items → compact list (SG7). Empty hour runs: per-hour lines on desktop (board 03), one "10–15" gap row on mobile (board 05), both rendered and switched by CSS `display:none`. Layout is a named-areas grid so the count sits beside the date block under 640 px; statusline is `position: sticky` at the bottom. Only `DateColumn`'s block uses `--color-date`. Slice 1 adds no animation (strike is static), so reduced motion needs only the existing token remap. Sign-out stays as a ≥ 44 px control in the date column. No key hints in the statusline until they work.

## Threat Matrix

N/A — no shell, subprocess, VCS/PR automation, executable classification or process integration. The new HTTP route is covered by R15 (401, RLS); the seed is a DB-only CLI with RLS-enforced scope.

## Migration / Rollout

No migration. Merge in order; each PR reverts alone (PR 4 restores hello-world, and PRs 5-6 fill an already-working page). Seeded rows removable with `--remove`.

## Risks

- `profiles.timezone` is `UTC` for new users until slice 7: their "today" is the UTC day (the date column shows the timezone). Mitigation: seed `--timezone`.
- DST: the tick uses instant differences (safe); rail rows enumerate local hour numbers, so a spring-forward day may show a nonexistent 02 line and a fall-back day a repeated hour (cosmetic, ordering stays by instant).
- Rollover can lag up to 60 s (minute tick) when the tab is active; focus refetch covers throttled tabs.
- `listOwn` loads every note (no body): fine at demo scale, revisit with the notes list.
- Bundle: `@onti/shared` pulls `date-fns` + `@date-fns/tz` (tree-shaken) and TanStack Query is new; record `vite build` size in PR 3/4.
- Adapter has no automated DB test (none exist in repo); verified through the seed run.
