# Design: Slice 2 — Timezone, capture, snooze and done/undo

## Technical Approach

The CONTRACT math already exists in `packages/shared` (`parseCapture`, `snoozeOneHour`, `snoozeTomorrow`, `markDone`, `undoDone`, `localTimeOn`); this slice is plumbing. The **server decides and stamps** every write (Clock + profile timezone, row lock, ownership, validation). The **client previews and predicts** with the same shared functions, patches the `['today']` cache optimistically, and lets the server response and a refetch have the last word. API stays hexagonal (domain → application → infrastructure); `packages/shared` stays IO-free. Serves proposal items 1-9 and Q1-Q9. Format follows slice 1: decision table, then flow, files, contracts, tests, delivery plan. Threat matrix: N/A (no shell, subprocess or VCS automation; HTTP routes covered by R15).

## Data Flow

    key x/s h ─▶ useReminderActions ─ onMutate: applyReminderChange(['today']) ─▶ UI updates now
                       │ POST /notes/:id/{snooze|done|undo}  (Bearer, no client time)
                       ▼
     authenticate ─▶ use case: clock.now() (+ profile tz) ─▶ notes.mutateReminder(identity, id, decide)
                       asUser tx: select … for update (id, user_id) ─▶ decide() ─▶ update ─▶ {note}
                       ▼
     200 {note} ─▶ onSuccess patch ─▶ onSettled invalidate ['today'] (when last in flight)
     4xx/5xx   ─▶ onError: restore snapshot + message; 401 ─▶ onSessionExpired

    c ─▶ CommandBar ─ previewCapture(input, displayNow, tz) ─ ↵ ─▶ insert (temp id) ─▶ POST /notes {title, tags, dueAt}
         └▶ asUser tx: upsert tags ─▶ insert note ─▶ insert note_tags ─▶ 201 {note} ─▶ replacesId patch

    /today.timezone === 'UTC' & browser ≠ UTC ─▶ PATCH /me {timezone} ─▶ invalidate ['today']

## Interfaces / Contracts

```ts
// ports.ts additions
interface ProfileRepository {
  setTimezoneIfDefault(i: Identity, tz: string): Promise<string | null>
}
interface NoteRepository {
  mutateReminder(
    i: Identity,
    id: string,
    decide: (r: Reminder) => Reminder,
  ): Promise<NoteRecord | null>
  createOwn(
    i: Identity,
    input: { title: string; dueAt: Date | null; tags: { slug: string; name: string }[] },
  ): Promise<NoteRecord>
}
// shared
const snoozeRequestSchema = z.object({ preset: z.enum(['hour', 'tomorrow']) })
const captureRequestSchema = z.object({
  title: z.string().trim().min(1).max(200),
  tags: z
    .array(z.string().max(40).regex(TAG_SLUG))
    .max(10)
    .refine((t) => new Set(t).size === t.length), // unique slugs
  dueAt: instant.nullable().transform(truncateToMinute), // seconds/ms dropped (Decision 6)
})
type ReminderChange =
  | { type: 'snooze'; id: string; preset: 'hour' | 'tomorrow' }
  | { type: 'done'; id: string }
  | { type: 'undo'; id: string }
  | { type: 'insert'; note: NoteResponse; replacesId?: string }
```

Status matrix: `PATCH /me` 200/400/401/404; `POST /notes` 201/400/401; `snooze` 200/400/401/404/409; `done` 200/400/401/404/409 (no reminder); `undo` 200/400/401/404. `400` on done/undo is only a malformed or wrongly typed body (Fastify-native, Decision 3).

## Migration / Rollout

No migration (RLS "for all" policies and `authenticated` grants already allow owner insert/update; `tags` unique `(user_id, slug)` supports the upsert; `profiles` and `notes` have `updated_at` triggers). `docs/db/schema.md` unchanged. One PR, merged as a whole; commits are ordered so each is green alone, and the web commits (4-7) only add UI on endpoints that stay harmless, so a partial revert of them is safe. Created notes and a stored timezone remain valid after a revert.

## Risks

- DB adapters (lock, upsert, tz update) have no CI coverage; mitigated by the manual checklist and thin adapters with logic in tested use cases.
- Optimistic helper can drift from `getToday`: the parity test is the guard. Display clock skew can place an item differently for up to a refetch; `onSettled` corrects it.
- Plain notes (Q1) are invisible until slice 5; capture succeeds with no row appearing except the "other notes" count. The preview line states "note, no reminder".
- TanStack scope ordering: `onMutate` runs when a write is queued, the request when the previous one settles; the "first of two fails" component test must prove the rollback converges.
- Pre-existing: the `QueryClient` cache is not cleared on sign-out, so another user signing in on the same tab could briefly see the previous `['today']` data; out of scope, flagged for a follow-up.
- Size: ~2,460 lines versus the 800 budget in one PR (`size:exception` accepted); mitigated by commit-by-commit review (see Delivery plan).
