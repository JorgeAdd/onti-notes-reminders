# Design: Slice 5 — All notes and text search

## Technical Approach

One read endpoint, one repository method, one lazy web view. `GET /notes?q=` returns the caller's notes newest first; a non-empty `q` adds a word-prefix match on the existing `notes.search` tsvector (`simple`, GIN index). **No migration.** The API sanitizes `q` into plain terms in the domain layer; only the Postgres adapter knows tsquery syntax, and it builds it from those terms, never from raw input. The web gets a second view (`today | notes`) owned by `App`, with no router and no URL state. Slice-5 code lives in new files; edits to shared files are small, append-only or in their own section (rebase plan below). Serves proposal items 1-7 and Q5-Q8 (#1094, full wording). Threat matrix: N/A (no shell, subprocess, VCS automation or process integration). The injection surface is the query string and is covered by Decision 2 and its tests. Format follows slice 2: decision table, flow, files, contracts, tests, delivery plan.

## Data Flow

    `/` or "Search" ─▶ App: setView('notes') ─▶ lazy NotesContainer (input focused)
         term ─ debounce 200 ms ─▶ useQuery ['notes', term] ─▶ GET /notes?q=term   (Bearer)
                                                    ▼
      authenticate ─▶ searchNotes: clock.now() + profile tz ─▶ searchTerms(q) ─▶ notes.searchOwn
                                                    ▼
      asUser tx: select (user_id = me [and search @@ to_tsquery('simple', $1)]) order created_at desc limit 50
                 ─▶ count(me) ─▶ tags for the ids ─▶ rows ─▶ excerptOf ─▶ 200 {now, timezone, total, notes}
                                                    ▼
      NoteList (read-only rows)   SearchStatusline "SEARCH · term · n of total"
    esc / "Back to today" ─▶ App: setView('today') ─▶ TodayContainer (cache first, refetch)

## Interfaces / Contracts

```ts
// shared/notes-list.ts
// excerptMax is in UTF-16 code units, the unit z.string().max() counts
export const SEARCH_LIMITS = { qMax: 200, resultsMax: 50, excerptMax: 120 } as const
export const notesQuerySchema = z.object({ q: z.string().max(SEARCH_LIMITS.qMax).optional() })
export const noteListItemSchema = z.object({
  id: z.uuid(),
  title: z.string().min(1),
  tags: z.array(z.object({ name: z.string().min(1), slug: z.string().min(1) })),
  dueAt: instant.nullable(),
  doneAt: instant.nullable(),
  excerpt: z.string().max(SEARCH_LIMITS.excerptMax),
})
export const notesListResponseSchema = z.object({
  now: instant,
  timezone: z.string().min(1),
  total: z.number().int().nonnegative(),
  notes: z.array(noteListItemSchema).max(SEARCH_LIMITS.resultsMax),
})

// application/ports.ts (appended)
export interface NoteListRow {
  id: string
  title: string
  bodyHead: string
  tags: { name: string; slug: string }[]
  dueAt: Date | null
  doneAt: Date | null
}
interface NoteRepository {
  /** Caller's notes newest first, optionally narrowed to notes matching every term as a word prefix. */
  searchOwn(
    identity: Identity,
    query: { terms: string[]; limit: number },
  ): Promise<{ rows: NoteListRow[]; total: number }>
}
// domain
export const searchTerms: (q: string | undefined) => string[]
export const excerptOf: (bodyHead: string) => string
// infrastructure only
const tsqueryOf = (terms: string[]) => terms.map((t) => `'${t}':*`).join(' & ')
```

Status matrix: `GET /notes` 200 / 400 / 401 / 500. Web: `request('GET', '/notes' + (term ? '?q=' + encodeURIComponent(term) : ''), token)`; 401 stays `UnauthorizedError`.

## Tokenizing: the URL risk, and how the API behaves either way

Measured on local Postgres 16.15: `to_tsvector('simple', 'Staging URL and test accounts staging.client-b.example')` gives `'accounts':5 'and':3 'staging':1 'staging.client-b.example':6 'test':4 'url':2`. The https host is **one token**. The Postgres test (commit 3) pins this table as characterization.

| Case                                         | Measured (Postgres 16.15)                                                                                         | API behavior                                                                                                                                                                                                               |
| -------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Host kept as one token                       | `staging.client-b.example` is ONE token (`'staging.client-b.example':6`), next to the separate word `'staging':1` | `staging:*` matches (the word, and the host by prefix). `'client':* & 'b':*` and `example:*` do **not** match inside the host. Pasting the whole URL finds nothing (terms split on `.`). Documented limit, no code branch. |
| Hyphenated word                              | `client-a` gives `client-a`, `client` and `a`                                                                     | `client` and `a` (the split terms) match. Same code.                                                                                                                                                                       |
| `client-a/web` (N1 body)                     | `/web` is a `file` token, so `web` does not match N1                                                              | `web:*` does not match N1. Documented limit, same as the host row.                                                                                                                                                         |
| Prefix and case                              | `collab:*` and `COLLAB:*` both match "Collaborators"                                                              | Terms are lowercased first; both inputs find the note. Asserted.                                                                                                                                                           |
| `²` or `Ⅻ` (`\p{N}` but not a tsvector word) | Yields an empty tsquery with a NOTICE; matches nothing, no error                                                  | `200` with an empty list (`total` unchanged). Documented limit, asserted by the Postgres test.                                                                                                                             |

C9 holds: `staging` matches N2 on its title and N8 on its title **and** body. Proof that **bodies are searched at all** uses N1 only, whose title has no body words: `collaborators` and `release` return N1 alone. The Postgres test asserts C9 and these two terms as requirements; the host, hyphen, `file` and numeral rows are pinned as characterization (a non-prefix inner word not matching is a documented limit, not a goal). **The in-memory fake splits on `[^\p{L}\p{N}]`, so it DOES match `client`, `example` and `web`; fake-based tests must not assert those terms** (only the Postgres test may). Other documented limits: terms made only of characters the tokenizer ignores (`²`, `Ⅻ`) match nothing, no stemming (`deployments` does not find `deployment`), no accent folding, word characters of non-ASCII scripts depend on the database locale.
