# Design: Slice 6 — Web Push notifications

## Technical Approach

Hexagonal and test-first. The pure parts (payload rules, body stripping, dispatch, token codec) sit behind ports and run in Vitest with a fake claimer, fake sender, in-memory subscriptions and a mutable fake clock; no test touches the network or Postgres in CI. Infrastructure is thin: one SQL claim statement, a `web-push` adapter, an interval scheduler with an injectable timer, and routes registered only when an optional `push?` dependency is present, so every existing server test stays untouched. Serves the proposal and the specs (`push-scheduler`, `push-subscriptions`, `push-actions`, `notification-permission`), cites R7, R9, R10, R15, R16, C2, C3, C5, C7, C15, SG17, ADR-001, ADR-002, ADR-004 and CLAUDE.md rules 8-19 without restating them. Threat matrix: N/A (no CLI routing, shell, subprocess, VCS automation or process integration); the HTTP and secret surface is covered by decisions 12-17 and Risks.

Slice 4 runs in parallel and owns the note wire type, `/notes/:id`, `GET /today`, `DateColumn`/`DayPage` and a markdown-to-plain-text helper. Slice 6 stays in NEW files: `application/push-ports.ts`, `test/push-fakes.ts`, `packages/shared/src/push.ts`, `features/push/*`. Edits to shared files are small and listed: `server.ts` (one optional dep), `main.ts`, `config.ts`, `database.ts`, `messages.ts` (key appended last), `App.tsx`, `DayPage.tsx`, `DateColumn.tsx`, `MobileBar.tsx`, `index.ts` (shared exports).

## Data Flow

    tick (30 s) ─▶ claimDue(now) ─▶ UPDATE … SKIP LOCKED ─▶ rows (note, tags, tz)
                       │                    (marks notified_due_at before any send)
                       ▼
          per reminder ─▶ listForUser ─▶ none: stop (C7)
                       ▼
          buildPushPayload ─▶ tokens.sign(24 h) ─▶ sender.send × devices ─▶ sent | gone | failed
                                                         │                     │      │      │
                                                         ▼                     ▼      ▼      ▼
                                            push service ─▶ SW push     reset  delete  count/drop

    SW click (Done / +1 h) ─▶ POST {apiUrl}/push-actions/{done|snooze} {token}
          ok ─▶ postMessage onti:refetch ─▶ queries invalidated
          fail ─▶ focus window + postMessage onti:action  |  openWindow /?action&note&due
                       ▼
                 PushBridge ─▶ fetchToday ─▶ note open and dueAt == due? ─▶ JWT markNoteDone / snoozeNote ─▶ refetch

    subscribe (control) ─▶ requestPermission (click only) ─▶ pushManager.subscribe ─▶ POST /push-subscriptions
    sign-out ─▶ getSubscription ─▶ DELETE /push-subscriptions + unsubscribe() (≤ 2 s) ─▶ session cleared

## Concrete Specifications

### Claim statement (`PostgresReminderClaimer`, owner role, no `asUser`)

```sql
with due as (
  select n.id from notes n
  where n.due_at is not null and n.due_at <= $1 and n.done_at is null
    and n.notified_due_at is distinct from n.due_at
  order by n.due_at, n.id
  limit $2
  for update skip locked
), claimed as (
  update notes n set notified_due_at = n.due_at
  from due where n.id = due.id
  returning n.id, n.user_id, n.title, left(n.body, 2000) as body, n.due_at
)
select c.id, c.user_id, c.title, c.body, c.due_at,
       coalesce(p.timezone, 'UTC') as timezone,
       coalesce((select json_agg(t.name order by t.slug)
                 from note_tags nt join tags t on t.id = nt.tag_id
                 where nt.note_id = c.id), '[]'::json) as tag_names
from claimed c left join profiles p on p.id = c.user_id
```

Kysely `sql<Row>` template with `$1 = clock.now()`, `$2 = CLAIM_BATCH`. The partial index `notes_open_due_idx` serves the scan. The `notes_set_updated_at` trigger bumps `updated_at` on a claim (nothing reads it; documented in schema.md). The predicate must equal `isNotificationDue`; a `[pg]` parity test enforces it.

### Payload rules (`buildPushPayload`, pure)

- Title: `HH:MM · <title>` with `Intl.DateTimeFormat('en-GB', { timeZone, hour: '2-digit', minute: '2-digit', hourCycle: 'h23' })`; invalid zone falls back to `UTC`.
- Body: strip markdown per line (fences dropped, heading/list/quote markers, emphasis, inline code ticks, `[t](u)` to `t`, `![a](u)` to `a`), drop lines empty after stripping, take the first 2, join with `\n`, cut to 120 code points (119 plus `…`). Then append the tag display names as a last line (`Client A, Client B`). No body and no tags: empty string.
- `tag` = note id (a newer push for the same note replaces the older one; the SW sets `renotify: true`). `noteId` and the id appear only in `tag`/`data`, never in visible text (rule 13).

```ts
// packages/shared/src/push.ts (zod, no IO)
```

### Config (names only; values never printed)

Required together: `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` (`mailto:` or `https:`), `PUSH_ACTION_SECRET` (at least 32 characters), `API_PUBLIC_URL` (URL, trailing slash trimmed; `http://localhost` allowed for dev). Error text: `Incomplete push configuration. Missing: A, B` or `Invalid push configuration: A`. `API_PUBLIC_URL` travels in the payload (`apiUrl`), so the SW needs no build-time API URL.

### Wiring (`main.ts`)

`config.push === null`: nothing changes (no sender, no scheduler, no `push` dep). Otherwise build `WebPushSender`, `HmacActionTokens`, `PostgresReminderClaimer`, `PostgresPushSubscriptions`, `makeDispatchDue`, `createScheduler`, and pass `push` to `buildServer`. `shutdown()`: `scheduler.stop()`, `app.close()`, `db.destroy()`. The scheduler starts after `app.listen`.

### Routes (`registerPushRoutes(app, deps, authenticate)`)

`buildServer` destructures `push` and, when present, calls `registerPushRoutes(app, push, authenticate)` right after `/health`. Subscribe, unsubscribe: JWT (`401` missing or invalid, `400` invalid body). Actions: token only (rule 18 exception, ADR-004). CORS: the existing `@fastify/cors` handles the SW's cross-origin preflight (`POST`, `Content-Type: application/json`); `CORS_ORIGINS` must contain the Vercel production origin (preview origins fall back to opening the app).

### Service worker behavior (`public/sw.js`)

- `push`: parse `event.data.json()` in `try/catch`; always `registration.showNotification(title, { body, tag, renotify: true, icon: '/icons/icon-192.png', data: { noteId, dueAt, apiUrl, token }, actions })`; `actions` only if `Notification.maxActions > 0`, sliced to it. Invalid payload: title `Notes + Reminders`, no actions.
- `notificationclick`: `close()`. Body tap: focus a window or `openWindow('/')`. Action tap: `fetch(new URL('/push-actions/' + action, apiUrl), { method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify({ token }) })`; `res.ok`: `postMessage({ type: 'onti:refetch' })` to every window client (`includeUncontrolled`); otherwise or on throw, the fallback of decision 19. Everything inside `event.waitUntil`.

### Manifest, icons, headers, env

- `public/manifest.webmanifest`: `name` "Notes + Reminders", `short_name` "Notes", `start_url` and `scope` `/`, `display` `standalone`, two PNG icons (192, 512). `background_color` and `theme_color` are raw hex because a manifest cannot read CSS variables; they equal the resolved `--color-desk` and `--color-page` (light), and a test fails if tokens drift. This is a narrow, accepted exception to CLAUDE.md rule 8 (manifest only; light-mode values).
- Placeholder PNGs (192, 512, 180 apple-touch) generated once with a throwaway zlib script (solid desk color, inset ink square); binary, outside the line budget. `index.html` gains `<link rel="manifest">`, `<link rel="apple-touch-icon">`, `<meta name="theme-color">` (the slice 8 inline script and its parity test are untouched).
- `vercel.json`: `headers` for `/sw.js` (`Cache-Control: no-cache`) and `/manifest.webmanifest` (`Content-Type: application/manifest+json`); `rewrites` unchanged (static files win before the SPA rewrite).
- `lib/env.ts`: `VITE_VAPID_PUBLIC_KEY` optional, `''` treated as absent.

### Control states and copy (`messages.notifications`, appended last)

| State       | Trigger                                               | Render                                                                                                      |
| ----------- | ----------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |

Tokens only (`--size-target`, `--focus-ring`, `--text-meta*`, `--color-ink*`, `--radius-control`), no `--color-date`, no hardcoded copy. Phone variant: a short button in the bar (between Tags and Capture); long sentences render as a muted `role="status"` line above the bar. Accepted default: keep the bar slot after a manual check at 375 px (four 44 px targets, no horizontal scroll); if it does not fit, phones use the date column only.

## Migration / Rollout

1. Apply the backfill migration to Supabase first. If the scheduler ran before it, the first tick would send every overdue reminder.
2. Merge PR1 and PR2 (push stays off: no config).
3. Only after the backfill is applied: set Railway variables (names in `docs/roadmap.md`), one non-sleeping instance, and deploy; then Vercel `VITE_VAPID_PUBLIC_KEY`; then merge PR3 (after slice 4 is merged and PR3 is rebased).
4. Rollback: unset the VAPID config (scheduler and routes off) or revert the PRs; the backfill only set `notified_due_at`, so no data repair. Rotating the VAPID keys kills subscriptions; rotating `PUSH_ACTION_SECRET` makes old notifications fall back to opening the app.

## Risks and resolved contradictions

- **Resolved 1: owner-role subscribe.** ADR-001 is amended (2026-10-08, docs-first commit): the subscribe reassignment is the one owner-role statement allowed besides the scheduler (decision 16).
- **Resolved 2: guarded fallback.** ADR-004 decision 5 now carries the note id and `due_at` and runs the action only when Today still matches (decision 19); ADR-004 decision 6 records the `401`/`404`/`409` codes (decision 15).
- **Resolved 3: delivery.** The token codec moves to PR1 (dispatch embeds the token). Three PRs labelled `size:exception`, `delivery_strategy: exception-ok` (human decision).
- **Accepted 4: manifest colors.** `theme_color` and `background_color` are raw hex (a manifest cannot read CSS variables) and icon PNGs carry raw colors: a narrow rule 8 exception, guarded by a parity test against the light-mode tokens.
- **Accepted 5: mobile bar slot.** SG14 defines three bar buttons; the slot adds a fourth. Manual check at 375 px; if it does not fit, phones use the date column only.
- **Accepted 6: sign-out wait.** `App.tsx` says the screen never waits on the network; sign-out now waits at most 2 s, only when this browser is subscribed, noted as an exception in that comment.
- **Interpretation (rule 12):** notification title format and action labels are server-built, so they live in `PUSH_COPY` in shared, not in the web `messages.ts`. The spec's "app name in the payload" is carried as `appName` and used by the SW as the fallback title.
- **At-most-once loss** on a crash between claim and send (accepted, C7: Today still lists the item). TTL 3600 s means a device offline over an hour misses it.
- **Secrets:** `PUSH_ACTION_SECRET` leak allows forged actions until rotated; never logged. Logs never contain endpoints (they are capability URLs), tokens, keys or payloads.
- **SSRF residue:** no push-service allowlist, only https and public-host checks; the POST body is encrypted and not readable by the target.
- **No failure rate limiter** (decision 15) and **no per-user subscription cap**; both go to `docs/backlog.md`.
- **Slice 4 conflicts:** `server.ts`, `main.ts`, `ports.ts` (not touched), `DayPage`, `DateColumn`, `MobileBar`, `App.tsx`. Hunks are small and placed away from likely slice 4 edits; rebase PR3 after slice 4 is merged. Migration timestamps must stay unique on rebase.
- **Single instance:** with N replicas the claim is safe, but each replica would run a scheduler; fine by `SKIP LOCKED`.
- **`updated_at` bump** on claim and backfill (trigger); nothing reads it.
- **Unverifiable in CI:** real delivery, iOS behavior, action buttons per browser.
- **Design size:** the SDD skill's 800-word cap was exceeded on purpose; the request required decisions, files and tests per PR.
