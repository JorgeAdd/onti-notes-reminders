# Design: Slice 4 — Note editing and markdown

## Technical Approach

Hexagonal and additive, following the existing patterns. Pure rules go to `packages/shared/src/domain` (undated selection, plain-text stripper, `clearReminder`, tag-list and due-time parsing); the API gets thin use cases over the `NoteRepository` port and thin routes; the web adds a note view inside the All notes container and a lazy markdown chunk. No migration (schema already has `body`, `created_at`, cascade, RLS). Serves the proposal and specs (`note-view`, `note-editing`, `markdown-rendering`, `undated-list` and the three deltas); behavior is cited from CONTRACT R8, R14, R15, R19, R20, C10, C11, C13, C14 and ADR-001..003, never restated.

Two milestones, as in the proposal: **PR1 read side**, **PR2 write side**. Both exceed the review budget; the human chose two PRs labelled `size:exception` (delivery_strategy `exception-ok`, no chain): PR1 = slices 1a + 1b + 1c (about 1,825 lines), PR2 = slices 2a + 2b + 2c (about 1,660 lines); the slices become groups of work-unit commits (see Size forecast). Every decision below is tagged with the milestone it belongs to.

## Data Flow

    GET /today ──▶ getToday ─▶ own = listOwn (createdAt) ─┬▶ tag filter ▶ buildDayResponse(page…, undated)
                                                          └▶ selectUndated(own)  (unfiltered, JS)
    capture (no time) ─▶ applyReminderChange ─▶ insertUndated (same comparator) ─▶ settle(replacesId) ─▶ refetch == patch

    Today undated row / All notes row ─▶ App {view:'notes', noteId, edit:false}
    Today `e` on focused row          ─▶ App {view:'notes', noteId, edit:true}
    NotesContainer (mounted, term/tag kept) ─▶ NoteContainer ─ GET /notes/:id ─▶ NoteBody ─ lazy ─▶ MarkdownBody
                                                   │ e / Edit ─▶ NoteEditForm ─ PATCH ─▶ setQueryData(note) + invalidate(notes, day)
                                                   │ d / Delete ─▶ StatuslineConfirm ─ DELETE (204) ─▶ remove(note) + invalidate ─▶ close
                                                   └ esc ─▶ list ─ esc ─▶ Today (refetch shows new counts, undated, rail)

    API: route ─▶ use case ─▶ NoteRepository.findOwn | updateOwn (row lock, tags upsert) | deleteOwn ─▶ Postgres as `authenticated`

## Migration / Rollout

No migration. Both new fields are additive on the wire: an old web ignores them (zod strips unknown keys), but a new web parsing an old API fails on the missing `createdAt` and `undated`, so deploy the API (Railway) before the web (Vercel) for each PR (PR1 carries the new fields; PR2 adds routes the web calls). Rollback per the proposal: revert PR2 (2c, 2b, 2a), then PR1; hard-deleted notes are not recoverable by design. Regenerate the lockfile after slice 6 rebases (both touch `package.json`).
