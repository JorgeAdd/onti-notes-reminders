# Design: Slice 3 — Day navigation and tag filter

## Technical Approach

Extend `GET /today` with `?date=YYYY-MM-DD&tag=slug` (backward compatible, no new route, no port change). The page assembly moves into one pure shared function, `buildDayResponse`, used by the use case **and** by the optimistic patch, so the two cannot drift for the parts both know; a parity test against the real `makeGetToday` guards the rest. The viewed day and tag live in the URL (`?d=&tag=`, History API, no router). The query key is `['day', date|'today', tag|null]`; every write settles by invalidating the `['day']` prefix, because a snooze moves an item between days. Serves proposal Q1-Q4, CONTRACT R1, R3, R6, R12, C8. Threat matrix: N/A (no shell, subprocess or VCS boundary; query params are validated and only ever narrow the caller's own notes, R15). Format follows slice 2.

Answer first: **day navigation is calendar-string arithmetic** (`'2026-03-07' + 1`), never "+24 h"; the server turns a date into a window with local-midnight arithmetic. That is what keeps D1 (23 h) and D2 (25 h) days correct.

## Optimistic patch: the two riskiest cases

| Case                                | Behavior designed                                                                                                                                                                                                                                                                                                                                                                                 | Proof                                                                                                                                                                       |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Snooze moves an item to another day | Today `s t` → Fri 09:00: leaves the page, `otherCount + 1` (filtered: enters `others` with its date). Viewing Fri, `s h` → due is now + 1 h, i.e. **today**: leaves Fri. Viewing a past day, `s h` also lands on today. Focus passes to the next row (slice 2 `afterRemoval`). Inactive day caches are removed on mutate; settle invalidates `['day']`, so the destination day is fetched fresh.  | Parity test over views {today, today + tag, Tue 6, Fri 9} × {snooze h/t, done, undo}; web test for focus handoff and for navigating to the destination day after the write. |
| Capture on a filtered view          | No tag is injected (R11: preview equals saved). Matching tag → page or `others`. No tag → `hiddenCount + 1`, the row never renders. ## Migration / Rollout

No migration, no schema change (`docs/db/schema.md` unchanged). Backward compatible request: `/today` without params is today's page. The response gains required fields, so a web build that deploys before the API fails `zod` parsing and shows the existing load-error and retry state (loud, never a wrong page); the API ships in the same merge and the window is minutes. Revert the PR to roll back; `?d=`/`?tag=` are ignored by older builds. Query-string params coexist with Supabase auth, which uses the URL hash.

## Risks

- `TZDate` at a skipped local midnight (Havana, Santiago): covered by the tiling test; if red, fix in `dayWindow` using `localTimeOn`'s gap rule.
- Cache key drift: any remaining `['today']` silently stops patching and invalidating. Guard: one key factory and a grep gate.
- `[`, `]`, `#` need AltGr on some keyboard layouts and the layer ignores `alt`. Desktop-only limitation; mobile has buttons. Not changed here (SG10 fixes the keys).
- Size: ~3,100 lines against 800; mitigated by commit-by-commit review and the single human-approved exception.
- Slice 5 rebase: `App.tsx` `load` signature, `keys.ts` unions, `MobileBar` order, `messages.ts` tail. Kept append-only.
